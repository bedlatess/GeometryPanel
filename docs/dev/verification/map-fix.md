# 0.3.1 地图兼容修复

用户反馈：网页仍只有经纬度，并提示“坐标类型未标明”，官方 App 能显示道路、小区。

## 已确认的问题与修复

0.3.0 仅允许少数坐标字符串。`vehicleHomePageV2` 的位置字段如果带有数字、厂商标签或其它不认识的值，网页就会丢掉地图和导航入口，即使经纬度有效。用户看到的提示能确认这个分支被触发，但本轮没有读取真实账号响应，不能声称知道用户收到的具体标签。

恢复发布物 `inline-12.decoded.js` 的 `_0x2457d7` 只把 `coordinateSystem` 透传成 `loc.crs`。`inline-18.decoded.js` 的 `_0x2e87b8` 并不读取该值：输入固定按 GCJ-02 使用，只有图源要求 WGS84 时才转换。

0.3.1 对这个车辆接口恢复相同的兼容约定：数字或不认识的标签使用 GCJ-02，标记为 `legacy-default`，不声称识别了数字枚举，也不声称服务端明确报告 GCJ-02。识别出的 GCJ-02/高德和 WGS84/GPS 标签仍按实际类型使用；明确的 BD-09、Web Mercator 等不兼容类型继续阻止错误标记。

有效位置会显示地图入口。未返回文字地址时，直接提示在地图里查看道路、小区和停车点；经纬度放在“查看坐标信息”下，并说明使用的坐标约定。

## 道路、小区文字的边界

经纬度只是位置，显示道路、小区名称还需要接口提供文字地址或地图服务把坐标转成地址。恢复的旧网页首页仅消费 `home.address`、`location.address`、`location.addressName`；对恢复发布脚本做了 `regeo/geocod/formattedAddress/formatted_address/逆地理` 的有界搜索，未发现旧首页独立进行逆地理编码的实现。它不能证明官方 App 采用相同方式，也不能证明服务端一定会给每辆车返回地址。

本次优先保留这些原始文字地址；缺失时使用可打开的高德地图看道路/小区标签与停车点。没有把经纬度改写成猜测的地址，也没有加入无授权地图密钥、未公开接口或其它地理服务。**面板里单独的一行文字地址仍取决于极核接口是否返回；未接入独立逆地理编码服务。**

高德官方 URI [标记文档](https://lbs.amap.com/api/uri-api/guide/mobile-web/point)支持 `coordinate=gaode/wgs84`，本次经 Context7 再次核对。地图仅在点击后加载，不携带账号、VIN 或登录信息；关闭即移除 iframe。

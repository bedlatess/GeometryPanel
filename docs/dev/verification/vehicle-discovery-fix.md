# 0.1.1 车辆识别修复

用户报告：短信登录成功，官方应用已有车辆，但网页提示没有可连接车辆。

静态对照确认，恢复发布物的 `inline-12.decoded.js:2176` 将响应 `data[]` 中的 `vinNo` 直接映射为车辆编号，没有要求它必须满足 17 位 ISO VIN。网页版额外增加了 `^[A-HJ-NPR-Z0-9]{17}$` 过滤，且将被过滤后的空数组显示成账号无车；相同限制也出现在车况、命令绑定与保存会话的读取中。

使用合成 15 位车架号可以复现：服务返回一辆车，旧解析得到零辆；修复后可以选择、读取、重新打开恢复，并在用户确认后向同一编号发送一次模拟鸣笛。另覆盖字母大小写、前后空白、缺失编号、非法路径和超长编号。所有编号都来自账号返回的记录，不生成或猜测车辆编号。

新解析保留返回记录数和未识别数，仅使用长度有上限的 URL 单段字符作为编号。界面分别显示可选车辆、已返回但未识别、服务确实返回零辆三种结果。统计不含手机号、token、UID、VIN 值或原始响应。

本次没有读取用户账号或其真实车辆列表，因此上述说明证明了代码缺陷和模拟回归结果，不能替代用户车辆的最终验证。如果新版本明确显示服务返回 0 辆，需继续排查上游账号/列表响应，不能仍归因于本地编号过滤。

为保证旧版安装能获得修复，Service Worker 安装新静态缓存时使用 `cache: reload`，避免从浏览器 HTTP 缓存取到旧首页。

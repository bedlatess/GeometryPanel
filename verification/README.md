# 开发验证记录

2026-11-07：生产构建和 16 项协议/模型测试通过。完整浏览器套件 28 项通过：Chrome 156.0.8078.80 与 Playwright WebKit 27.2，各 14 项，使用手机尺寸视口和本地 `/panel/` 子目录；这不等同于真实 iPhone Safari 验收。

- 演示模式控制按钮禁用，外部资源请求为 0，页面没有横向溢出。
- 浅/深色与点缀颜色选择保存到本机。
- Service Worker 安装成功，缓存仅含 7 个本站静态文件，无账号、验证码或车辆接口数据。
- 自动检查使用合成图片、验证码、token、车辆数据，覆盖登录、选车、重新打开恢复、换车、鸣笛确认与退出；列表重试不会重复登录。第一项演示检查也覆盖 320/390/430 像素宽度。
- 模拟鸣笛仅调用主路径一次，失败或取消不重试；过期登录不能发命令。登录密钥不可导出，localStorage 无明文 token；保存失败保留原车辆，退出后重开不会恢复登录。
- 离线重开保留连接、隐藏旧读数并禁用控制；恢复网络后读取。两个项目路径的账号和外观设置独立；手动更新保留会话且不删除其它应用缓存。

初次 WebKit PWA 检查发现 `context.route()` 与 Service Worker 共用时隔离不可靠，出现了实际验证码图片响应。测试在拼图尺寸与合成图片不符处停止，没有向真实服务提交短信、登录或车辆命令，也未使用真实账号。随后在应用启动前替换 `window.fetch`，保留路由拦截，并给本地测试页面与 worker 加 `connect-src 'self'` 限制。最终完整套件使用请求发出前的模拟。记录见 `network-isolation-incident.json`。生产应用不包含这些测试替换和本地测试限制。

增加测试主机 CSP 后，6 项 Chromium/WebKit PWA 子集再次全部通过，同时检查响应头中的限制确实生效。`npm audit` 报告全部依赖已知漏洞数为 0。

`browser-check.json` 为完整模拟套件结果摘要，`iphone-layout.png` 为 390×844 视口的演示界面全页截图。真实部署来源是否允许跨域请求、Safari 行为、账号登录和车辆实际响应仍需最后验证。

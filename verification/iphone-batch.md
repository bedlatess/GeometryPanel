# 0.3.0 续航修复、地图与 iPhone 使用功能包

用户已确认 0.2.0 车况充电、座桶和高声寻车通过；开锁上电与关锁关机稍后实车测试。整体 UI、字体和视觉设计按用户要求留到全部功能验收后。本批只增加功能必要的入口和说明。

## 续航

模型的续航优先级与旧客户端不一致，另有数组转 0 的数值解析问题。现按旧契约只使用主页 `hmiRidableMile`，电池额外同名值不参与；主页真实 0 保留，缺失/无效为未知。SOC、电压优先级保留。可复现输入、静态源位置和未观测到的实际响应边界见 [range-fix.md](range-fix.md)。不能把合成复现断言为用户实际响应。

## 可见地图

主动点击“显示车辆地图”后，在弹窗 iframe 加载固定 HTTPS 高德标记 URI；不附带账号、车辆编号或引用来源。设置 sandbox 和禁止 iframe 请求手机定位，关闭后移除 iframe，保留外部打开入口。坐标来源及已知/未知 CRS 的限制沿用已有导航适配。“带我去找车”是外部地图规划手机当前位置到车辆的步行路线，不是对车辆发送动作。

实际高德验证使用公开示例 `116.397,39.908` 与同样的沙箱设置，观察到地图 canvas、街道和示例标记并检查截图。该观察来自桌面 Chrome 的手机尺寸环境，不是实际 Safari 或车辆定位。自动回归中的地图页面则是请求前拦截返回的明确模拟 HTML，真实地图观察与模拟结果分开。

高德接口依据：[单点标记](https://lbs.amap.com/api/uri-api/guide/mobile-web/point)、[路线 URI](https://lbs.amap.com/api/uri-api/guide/travel/route)。外部地图后续可用性由提供方决定，因此保留新窗口打开入口，未增加地图 SDK 密钥或代理服务器。

## iPhone 与常用配置

- 使用 `display-mode: standalone` 和 iOS 的 `navigator.standalone` 区分桌面入口；帮助说明 Safari 与桌面入口可能分别保存登录，不能承诺跨入口会话自动共享。
- 重开按原有加密本机存储恢复会话，再进入选择的启动页；浏览器返回缓存的 `pageshow.persisted` 按一分钟节流读取。支持关闭回前台/恢复网络的自动读取；首次打开仍可正常读取，手动刷新保留。不新增后台轮询或自动车控。
- 离线设置显示静态页面准备状态，不把它称为离线车控。已读车况仍只留内存，离线重开不冒充当前数据；账号/API 响应不进入静态缓存。
- 更新检查等待注册与安装结果，合并并发检查，限制等待时间，区分暂无新版、准备完成、不可用和失败。新版仍须空闲时显式切换，命令弹窗中不能更新；更新后保持本机登录和常用配置。
- 启动首页、首页快捷操作、续航显示与自动读取开关独立放入 `core/preferences.ts`。沿用旧路径隔离存储并迁移旧外观/电压偏好；配置保存失败明确提示当前页有效。
- 配置导出只包含白名单、版本化偏好；导入拒绝额外账号字段、未知版本、错误类型及超大文本，失败不部分应用。恢复默认不改变账号或车辆。快捷座桶仍绑定车辆并经原有确认流程发送。

平台依据：[MDN standalone](https://developer.mozilla.org/en-US/docs/Web/Progressive_web_apps/How_to/Create_a_standalone_app)、[pageshow](https://developer.mozilla.org/en-US/docs/Web/API/Window/pageshow_event)。实际安装和 iOS 存储行为仍需要本批集中实机确认。

## 验证

本批完整 `npm run verify`：73 项单元测试、TypeScript/生产构建、100 项移动尺寸 Chromium/WebKit 检查通过。新场景覆盖零续航覆盖、真实零保留、面板内地图、配置恢复/导入/重置、存储失败、前台节流、安装状态和手动更新；更新检查与旧更新测试使用独立路径的修订号，防止测试之间互相制造新版。旧登录、车况和车控继续回归，未更改其请求协议。

第一次完整检查漏传本机 Chrome 路径，Chromium 在启动前报告不存在，随后停止该轮并配置已安装 Chrome 运行完整套件；环境失败未计入通过。开发中发现并修正了 select 的无障碍名称、模拟地图的 UTF-8 声明和测试更新修订号隔离，最终完整结果见 [iphone-check.json](iphone-check.json)。全部账号、车辆测试为合成数据，没有真实账号读取、短信或车辆命令。

# 几何面板 iOS

共用正式网页 `https://bedlatess.github.io/GeometryPanel/`，原生 Swift 只负责系统能力。需要 iOS 16 或更高版本。没有加入自己的账号服务器；网页账号保存在本机保险库。用户主动启用原生监控或任务时，资料同步进设备 Keychain，供原生任务使用。

## 两个 IPA

- `GeometryPanel-版本-unsigned.ipa`：常规版。供使用者自签，不需要 App Groups；含网页、蓝牙、通知和仪表能力。
- `GeometryPanel-版本-widget-unsigned.ipa`：可选桌面组件版。额外含 WidgetKit 扩展和 App Groups 配置；自签工具必须能处理扩展、App Groups 和相应授权。

两者都没有苹果签名，不能直接点击安装，也不承诺任何第三方自签工具均支持。自签者将 IPA 导入自己的工具、用自己的签名资料签署后安装。修改包标识时，工具需要一致处理主应用和扩展。组件版的组名在 `Resources/App.entitlements`、两个 Info.plist 的 `GeometryAppGroup` 中保持一致；有开发者账号的维护者应换成自己团队已创建的 App Group。基础版完全不依赖这个能力；不会签名时继续在 Safari 打开网页并添加到主屏幕。

签名密码、证书、Apple 账号不会进入仓库或构建流程。这里没有下载、远程注册或代签服务。

## 已实现的能力

| 能力 | 行为和边界 |
|---|---|
| 网页容器 | 正式 HTTPS 页面、失败重试、外链交给系统浏览器；主页面原生桥只允许本仓库路径和主 frame |
| 蓝牙扫描与连接 | 先扫描已知 B354 服务；没有结果时仅在前台扫描附近设备。用户在车旁选择并原生确认，连接后必须有 B354/B356/B357 服务与特征 |
| 蓝牙认证 | 恢复原包外帧、protobuf、两步 AES-ECB challenge-response；写入逐块等待回复，事务和连接都有超时 |
| 2.0 登记与查询 | 车主校验、五分钟云资料、云感应开关已开启；本机 8 字节身份保存在 Keychain。登记 ACK、云保存、车端查询分别处理 |
| 近距离车况 | 遥测及仪表流订阅；单位未验证的字段不猜。不会发送原包未包含的“开锁”帧 |
| 连接提醒 | 用户主动开启、单独请求通知权限。保持已认证连接时可在系统允许范围内处理断连提醒；不承诺自动开锁、后台无限运行或关闭应用后继续提醒 |
| 多账号与云监控 | 最多8账号、每账号16车；资料进设备 Keychain，默认关闭。前台每分钟轮询，后台仅 BGAppRefresh 系统机会运行，一次轮换一车，不承诺持续运行。账号/车辆 epoch、凭据变化取消旧任务 |
| 本地电池 / 充电历史 | AES-GCM 加密、排除备份；保留30天且电池最多2000样本、充电500段、事件500条。仅从收到的采样归纳；断测不推断充满。可分组清理本机历史 |
| 通知 | 充电开始/进度/明确充满/停止、低电量、云端报告离线、胎压告警、新未读消息。仅固定脱敏文本；网络失败不能当车辆离线，首次消息读取仅建立基线 |
| 自动任务 | 独立勾选签到、连续签到奖励、分享、发帖与精确清理；默认全部关闭。定时为系统机会执行；每步写入前持久化每日门闩，网络结果不明不盲目重试。原版点赞需额外确认可能切换已赞状态。发帖清理仅删除本次唯一确证的新文章 |
| 桌面组件 / 快捷指令 | 组件版显示最近车况，可配系统小/中/大尺寸与操作入口。AppIntents 打开已配置车辆，网页前台确认后才执行车控。普通 IPA 支持系统快捷指令，组件需要有效 App Groups 签名 |
| 仪表壁纸 | 从模板取得真实编号/显示配置，可选两图重新编码、本地 ZIP 或白名单官方 ZIP。严格检查 ZIP/PNG，再按 10950 协议传输和最终确认；可保存 / 分享官方 ZIP |
| 仪表投屏 | 用户系统录屏授权、ReplayKit 采集本应用、VideoToolbox H.264、三通道控制/协商/车端拉帧；红色按钮可停止，进入后台自动停止 |
| Gemini 仪表 OTA | 只支持原包确证的 AE5I 5寸 Sunplus Gemini 协议。选本地 .bin≤512 MiB，复制计算 MD5、读版本、原生再次确认后4096字节分块发送；收到最终响应也不能宣称刷写成功 |
| 工具 | 系统相机扫码只显示结果供复制；脱敏诊断导出；固定本仓库正式 Release 更新检查和自签安装说明。iOS 没有 Android VPN 登录捕获或 Root 保活模块 |

蓝牙 MAC 在 iOS 不可读取，因此不能照搬 Android 按 MAC 直连。3.0 钥匙和旧版已经标明未验证的自动解锁不能声称迁移完成。iOS 系统配对由 CoreBluetooth 在特征要求加密时提示，应用不能调用 Android 的 `createBond`。

仪表要求用户手动连接车辆热点，连接固定 `192.168.0.1` 的已知端口并要求 Wi-Fi 路径；接受车端连接也只接受该 IP。iOS 无通用 Wi-Fi Direct，部分车型可能无法提供兼容热点或拒绝 iOS 投屏握手。热点身份不能由 VIN 自动证明。投屏不含系统其它应用、音频、触摸反控；固件升级有独立流程，文件来源和车型兼容性仍需使用者确认。

## 本地维护和构建

需要 Mac/Xcode、可用的 iOS 模拟器和 XcodeGen：

```sh
brew install xcodegen
bash ios/scripts/build.sh
```

GitHub Actions `Verify iOS native and unsigned IPA` 在 macOS 构建。脚本从主项目 `package.json` 同步版本，先跑模拟器上的 XCTest，再构建两个 arm64 设备版。`ios/build/packages/` 包含两个 unsigned IPA、SHA256 和 `ios-verification.json`。记录当前提交、Xcode、模拟器结果、设备构建及每个 IPA 的哈希；没有真实 iPhone 或车辆时，不写成实机通过。

Xcode 工程由 `project.yml` 生成，不手工维护 pbxproj。原生桥 v1 的固定白名单扩展见 `verification/parity-bridge-v2.md`。桥限制可信主页面、主 frame、方法及参数大小，不提供任意 TCP、请求代理、JavaScript 执行或钥匙读取。地图 iframe 不能访问桥。普通切车 / forgetVehicle 清理当前蓝牙和仪表操作，保留独立多账号监控；退出全部由网页显式关闭监控 / 任务并同步空账号。所有原生任务在每次异步结果后再次检查账号和车辆作用域。

## 最后集中验收

在完整功能包统一部署后集中验收，保留已通过网页项目。新增原生重点为：多账号监控 / 历史与任务状态、快捷指令前台确认、扫码 / 文件导出、蓝牙现场能力、车辆热点壁纸与投屏。OTA 只在有已核对的适用固件时选择性验收，不为测试随意刷写。组件版只在自签工具支持 App Groups 时增加组件确认。功能结果以手机和车辆实际表现为准，自动测试使用合成数据。
